# 구매자 데이터

이 폴더에는 구매자 데이터의 구조와 처리 방식을 문서화한다. 실제 구매자 정보는 앱의 접근 통제된 저장소에 보관한다.

## 기본 프로필과 주문별 데이터

| 구분 | 저장할 값 | 사용 범위 |
| --- | --- | --- |
| `buyer_profile` | 구매자가 저장을 선택한 기본 배송지, 수령인 연락처, 선호 통화 | 다음 주문에도 쓸 수 있다. 저장한 결제 선호는 결제 승인 권한을 주지 않는다. |
| `purchase_request` | 이번 상품, 수량, 예산, 수령 기한, 이번에 지정한 배송지와 승인 조건 | 이번 주문에만 적용한다. 기본값을 바꾸려면 구매자가 별도로 저장을 선택한다. |
| `quote`와 결제 시도 | 판매처 견적 ID, 유효기간, 통화와 금액, 주문별 결제 시도 ID, 확인 상태 | 만료된 견적은 갱신한다. 거래 대조에는 필요한 식별값과 상태를 쓴다. |

## 개인정보 저장과 전달

1. 구매자는 로그인한 세션에서 HTTPS로 정보를 입력한다. 이름, 주소, 전화번호, 이메일처럼 개인을 식별하는 값은 백엔드가 DB에 쓰기 전에 인증 암호화(AEAD)한다. 프로필과 주문별 개인정보를 각각 암호화하고, 주문 확정 시 선택한 배송지 버전을 해당 주문에 연결한다.
2. 데이터 암호화 키는 키 관리 서비스(KMS)의 키로 감싸고, DB에는 암호문과 감싼 키 및 키 버전을 저장한다. 암호화할 때 서버가 정한 구매자 ID, 레코드 ID, 필드 용도를 부가 인증 데이터로 묶는다. 다른 주문이나 구매자의 암호문을 바꿔 끼우면 복호화 검증이 실패한다. [Tink 봉투 암호화](https://developers.google.com/tink/client-side-encryption), [AEAD](https://developers.google.com/tink/aead)
3. 상품 검색에는 필요한 조건만 전달한다. 한국 우편번호가 필요한 배송 견적은 구매자가 지정한 수령지에서 우편번호만 사용한다. 전체 주소를 판매처에 전송하는 연동은 전송 대상과 항목을 표시하고 승인받는다. 서버는 구매자와 주문의 소유 관계, 승인 범위와 만료를 확인한 뒤 승인된 필드만 메모리에서 복호화해 해당 판매처에 HTTPS로 전달한다.
4. 로그에는 요청 ID, 처리 결과와 오류 코드만 남긴다. 모델 입력, 분석 이벤트, 오류 추적 및 온체인 데이터에서 개인정보와 결제 비밀을 제외한다. 임시 입력은 만료 또는 취소 시 정리하고, 확정 주문의 배송 및 환불에 필요한 기록에는 별도 보관 기간을 적용한다.

## MVP 결제 흐름

**판매처 결제창을 사용하는 주문**에서는 상품과 견적을 보여준 뒤 구매자를 판매처의 공식 HTTPS 결제창으로 보낸다. 주소 자동 전달을 지원하는 공식 연동이 없으면 구매자가 그 화면에서 직접 입력한다. 카드 번호와 보안코드는 판매처가 제공하는 결제사 화면에 입력한다. 앱에 저장된 주소나 카드 선호만으로 결제를 시작할 수 없다.

**스테이블코인 주문**에서는 판매처의 현재 주문서가 제공하는 토큰, 네트워크, 수취처, 금액, 별도 수수료와 만료 시각을 구매자에게 보여준다. 주문에 필요한 서명은 구매자의 지갑에서 받는다. 개인키와 복구 문구는 구매자 지갑에만 둔다. 서명이 필요한 주문 데이터와 공개 체인에 기록되는 거래에는 배송지나 연락처를 넣지 않는다. 승인한 금액, 수취처 또는 네트워크가 바뀌면 새 견적을 제시한다. [연결된 판매처와 API 범위](../api_data/README.md#스테이블코인-결제-판매처)

**결제 완료 확인**은 판매처별 연동 권한에 따른다. 주문 조회 API나 서명 검증이 가능한 결제 알림이 있을 때 주문 ID, 결제 상태, 금액과 통화를 대조한다. 온체인 거래도 사용하는 경우에는 네트워크, 토큰 계약, 수취처, 수량, 거래 확정 여부까지 확인한다. 판매처 확인 수단이 없으면 ‘판매처에서 확인 필요’로 표시한다. 결제창에서 앱으로 돌아온 것만으로 주문 상태를 ‘결제 완료’로 바꾸지 않는다. 결제 요청을 전송하는 연동은 주문별 시도 ID와 멱등성 키를 사용하고, 응답이 끊기면 기존 거래부터 조회한다. [주문 상태와 결제 실행](../README.md#주문-상태와-결제-실행)

## 구현 시 검증 기준

- 구매자 A의 세션에서 구매자 B의 주소를 요청하면 복호화 전에 거부한다. 암호문 변조 또는 다른 주문으로의 복사는 인증 오류로 처리한다.
- 이번 주문에서만 바꾼 주소는 기존 프로필을 유지한다. 견적이 만료되거나 승인이 취소된 뒤에는 개인정보를 판매처에 전송하거나 새 결제를 요청할 수 없다.
- 결제 취소, 단순 복귀, 중복 알림과 응답 유실을 각각 검증한다. 결제 완료 기록은 확인된 거래 한 건당 한 번만 생성한다.

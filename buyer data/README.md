# 구매자 데이터

현재 MVP는 본인 기기에서 로그인 없이 사용한다. 최근 검색어와 결과는 Streamlit 세션에 둔다. 배송 프로필은 고객 기기의 CLI가 관리하고 선호와 피드백은 검색 앱에서 직접 저장하거나 삭제한다. 실제 파일과 DB는 저장소 밖에 둔다. 주문과 결제 기록은 후속 구현 범위다.

## 누가 어떤 데이터를 보관하는가

| 위치 | 데이터 | 보관 시점과 용도 |
| --- | --- | --- |
| [고객 기기](./local/README.md) | 고객이 저장을 선택한 수령인 이름, 연락처, 기본 배송지 | 다음 주문에서 다시 입력할 때 쓰는 암호화 파일. 기기 키링에서 키를 관리한다. |
| [서버의 고객별 메모리](./server/README.md) | 선호 통화, 신발 사이즈와 단위, 배송비 또는 도착일 우선순위 | 고객이 ‘다음에도 사용’을 선택했을 때 개인용 소유자 ID로 저장한다. 고객이 수정하거나 삭제할 수 있다. |
| 이번 요청 또는 주문 | 품번, 선택 옵션, 수량, 이번 예산, 견적 및 승인 상태 | 검색과 비교 중에는 세션에 두고 주문을 만들 때 선택한 값만 해당 주문에 연결한다. |
| 서버 공용 | 공개 상품명과 품번, 판매처 표시가, 환율과 코인 시세, 출처와 확인 시각 | 여러 고객이 같은 공개 데이터를 쓸 수 있다. 개인화된 가격과 배송 견적은 해당 고객의 주문에 둔다. |
| 판매처, 결제사 또는 고객 지갑 | 카드번호와 보안코드, 지갑 개인키와 복구 문구 | 카드 정보는 결제사 화면에서 입력하고 지갑 서명은 고객 지갑에서 처리한다. |

예를 들어 같은 `CW2288-111`의 판매처 표시가는 공용이다. A가 ‘평소 270 mm’를 저장하면 A의 다음 검색에만 적용한다. A가 선물용으로 이번에만 250 mm를 고르면 250 mm는 해당 주문에만 남고 기본값은 270 mm다. B가 같은 품번을 검색하면 B가 저장한 선호만 읽는다.

## 개인정보 전달

MVP에서는 주소와 연락처를 구매자가 판매처 결제창에 직접 입력한다. 검색 단계에는 상품 조건만 보내고, 배송 견적에 우편번호가 필요한 경우에만 해당 판매처에 전달한다. 개인통관고유부호가 필요하면 해당 주문을 처리하는 판매처나 운송사의 공식 입력 화면을 사용한다.

향후 공식 주문 API로 배송지 전달을 지원하면 전송할 필드와 수신처를 보여주고 주문별 승인을 받는다. 서버 보관이 필요한 주문 개인정보는 구매자와 주문 ID, 필드 용도를 결합해 인증 암호화하고 데이터 키는 KMS로 감싼다. 서버가 주문 소유자와 승인 범위, 만료 시각을 확인한 뒤 필요한 값만 복호화해 HTTPS로 전달한다. 로그에는 요청 ID, 처리 결과와 오류 코드만 기록한다. [Tink 봉투 암호화](https://developers.google.com/tink/client-side-encryption), [AEAD](https://developers.google.com/tink/aead)

## MVP 결제 흐름

**판매처 결제창을 사용하는 주문**에서는 상품과 견적을 보여준 뒤 구매자를 판매처의 공식 HTTPS 결제창으로 보낸다. 주소 자동 전달을 지원하는 공식 연동이 없으면 구매자가 그 화면에서 직접 입력한다. 카드 번호와 보안코드는 판매처가 제공하는 결제사 화면에 입력한다. 앱에 저장된 주소나 카드 선호만으로 결제를 시작할 수 없다.

**스테이블코인 주문**에서는 판매처의 현재 주문서가 제공하는 토큰, 네트워크, 수취처, 금액, 별도 수수료와 만료 시각을 구매자에게 보여준다. 주문에 필요한 서명은 구매자의 지갑에서 받는다. 개인키와 복구 문구는 구매자 지갑에만 둔다. 서명이 필요한 주문 데이터와 공개 체인에 기록되는 거래에는 배송지나 연락처를 넣지 않는다. 승인한 금액, 수취처 또는 네트워크가 바뀌면 새 견적을 제시한다. [연결된 판매처와 API 범위](../api_data/README.md#스테이블코인-결제-판매처)

**결제 완료 확인**은 판매처별 연동 권한에 따른다. 주문 조회 API나 서명 검증이 가능한 결제 알림이 있을 때 주문 ID, 결제 상태, 금액과 통화를 대조한다. 온체인 거래도 사용하는 경우에는 네트워크, 토큰 계약, 수취처, 수량, 거래 확정 여부까지 확인한다. 판매처 확인 수단이 없으면 ‘판매처에서 확인 필요’로 표시한다. 결제창에서 앱으로 돌아온 것만으로 주문 상태를 ‘결제 완료’로 바꾸지 않는다. 결제 요청을 전송하는 연동은 주문별 시도 ID와 멱등성 키를 사용하고, 응답이 끊기면 기존 거래부터 조회한다. [주문 상태와 결제 실행](../README.md#주문-상태와-결제-실행)

## 구현 시 검증 기준

- A와 B가 같은 품번을 검색해도 각자의 선호만 적용한다. A가 B의 메모리나 주문 ID로 읽기, 수정, 삭제를 요청하면 서버가 거부한다. 향후 주문 개인정보를 보관할 때에는 암호문 변조 또는 다른 주문으로의 복사도 검증한다.
- 이번 주문에서만 바꾼 주소는 기존 프로필을 유지한다. 견적이 만료되거나 승인이 취소된 뒤에는 개인정보를 판매처에 전송하거나 새 결제를 요청할 수 없다.
- 결제 취소, 단순 복귀, 중복 알림과 응답 유실을 각각 검증한다. 결제 완료 기록은 확인된 거래 한 건당 한 번만 생성한다.
